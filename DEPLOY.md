# JesusTime — Git + Working Copy + Cloudflare Workers Builds

This sets up an **iOS → Git → Cloudflare** deploy path that runs the *same* steps
as your Windows process. Your Windows flow keeps working unchanged — this is just a
second door into the same two Workers.

You have two Workers, so there are two Workers Builds connections (same repo, different
root directory):

| Worker            | Folder               | What it does                          |
|-------------------|----------------------|---------------------------------------|
| snowy-wood-35ec   | `jesustime-app/`     | Serves the app HTML (built by Vite)   |
| jesustime-friends | `jesustime-friends/` | Sync + ESV proxy + leaderboard        |

---

## 1. Put the project in one GitHub repo (from Windows, once)

From the folder that contains both `jesustime-app/` and `jesustime-friends/`:

```
git init
# copy the .gitignore and .node-version from this setup into the repo root
git add .
git commit -m "Initial commit: JesusTime app + friends worker"
git branch -M main
git remote add origin https://github.com/<you>/jesustime.git
git push -u origin main
```

`.gitignore` keeps `node_modules/`, `dist/`, `.wrangler/`, and the generated
`jesustime-app/worker-app.js` out of the repo. `worker-app.js` is regenerated by
`build-worker.cjs` on every build, so it never needs to be committed.

> Behind your corporate SSL inspection, point Git at your root CA so `git push` works:
> `git config --global http.sslCAInfo C:\path\to\corp-root.pem`
> (the same cert you used for npm/Wrangler). Avoid `http.sslVerify=false`.

## 2. Connect Worker #1 — snowy-wood-35ec (the app)

Cloudflare dashboard → Workers & Pages → **snowy-wood-35ec** → Settings → **Builds** →
Connect to Git → pick the repo. Then set:

- **Branch:** `main`
- **Root directory:** `jesustime-app`
- **Build command:** `npm ci && npm run build && node build-worker.cjs`
- **Deploy command:** `npx wrangler deploy`
- **Build watch paths** (optional but recommended): `jesustime-app/*`
  — so a push that only touches the friends folder won't rebuild the app.

That build command is exactly your `npm run deploy` chain, split into the build half
(`vite build` → inline into `worker-app.js`) and the deploy half (`wrangler deploy`).
The Worker name in `jesustime-app/wrangler.toml` is already `snowy-wood-35ec`, which
must match the Worker you're connecting — it does, so you're set.

---

## 3. Connect Worker #2 — jesustime-friends (sync)

Workers & Pages → **jesustime-friends** → Settings → **Builds** → Connect to Git →
same repo. Then:

- **Branch:** `main`
- **Root directory:** `jesustime-friends`
- **Build command:** *(leave empty)* — it's a single `worker.js`, nothing to build
- **Deploy command:** `npx wrangler deploy`
- **Build watch paths** (optional): `jesustime-friends/*`

The `KV` binding (`id = 8b1700098d...`) is already in
`jesustime-friends/wrangler.toml`, so the cloud deploy binds it automatically.

**Secrets:** `APP_TOKEN` and `ESV_TOKEN` live on the Worker (set earlier via
`wrangler secret put`). Deploys do **not** wipe secrets, so cloud builds keep using
them — nothing to re-enter. If you ever rotate them, set them once with
`wrangler secret put` (or in the dashboard) and they persist.

## 4. The iOS loop (Working Copy)

One-time:
1. Install **Working Copy**, unlock Pro (push is a Pro feature; free via GitHub Student pack).
2. Clone your GitHub repo inside Working Copy (it lists your GitHub repos after you sign in).

Each update:
1. In Claude (iOS), get the new `App.jsx`. Share/save it into the repo's
   `jesustime-app/src/App.jsx` — Working Copy exposes the repo through the Files app,
   so you can replace that one file directly.
2. In Working Copy: **Commit** (write a message) → **Push**.
3. Cloudflare Workers Builds sees the push, runs build + deploy for snowy-wood-35ec,
   and the live site updates. Build status shows as a check on the commit in GitHub.

> Optional one-tap: Working Copy has Shortcuts support, so you can make a "Commit + Push"
> shortcut and skip the manual taps.

Only `App.jsx` changes each time, so the repo holds all the scaffolding permanently and
your per-update action is just "replace one file, commit, push."

## 5. First-run checklist (do this once to trust the cloud build)

- [ ] Repo pushed to GitHub; `.gitignore` + `.node-version` in the repo **root**.
- [ ] snowy-wood-35ec connected (root `jesustime-app`, build + deploy commands above).
- [ ] jesustime-friends connected (root `jesustime-friends`, deploy command above).
- [ ] Trigger the first build (push a tiny change, or "Retry build" in the dashboard).
- [ ] App build succeeds; open the snowy-wood-35ec URL and confirm the page loads and the
      version badge shows your latest `APP_VERSION`.
- [ ] Friends build succeeds; sync/ESV still work (open the app on two devices, confirm a
      personal name added on one appears on the other after a foreground/pull).

## Notes / gotchas

- **Don't edit `App.jsx` on Windows and iOS at the same time.** A merge conflict inside a
  2 MB single file is miserable. Pull before you start, push when you're done. If you ever
  want a safety net, make iOS edits on a branch and merge on Windows.
- **Windows is unchanged.** Keep using `npm run dev` for live preview and `npm run deploy`
  to ship directly. Either path deploys to the same Workers.
- **wrangler version:** the app uses `npx wrangler deploy` (unpinned). For fully
  reproducible cloud builds you can add `"wrangler": "^4.98.0"` to `jesustime-app`'s
  devDependencies (matching the friends worker), but it's optional.
- **Alternative to Workers Builds:** a GitHub Actions workflow running the same
  `npm ci && npm run build && node build-worker.cjs && npx wrangler deploy` with a
  `CLOUDFLARE_API_TOKEN` secret achieves the identical result if you'd rather keep CI in
  GitHub. Say the word and I'll generate the workflow file.
